# Recorded-IQ validation — 2026-11-06

Hardware: Ryzen AI 5 340, `RyzenAI-npu6` / AIE2P; XRT 2.25.00, firmware
1.1.2.64. The default build is `ENGINE=AI MODEL=MLP_16X16 EQUALIZER_ALGORITHM=LS`,
16,384 samples/batch, 16 chunks/batch, two host slots. GNU Radio 3.10.9.2 and its
installed C++ NPU host were used with `/usr/bin/python3`. No simulator, model
retraining, host-module replacement, or classic-demapper fallback was used.

## Failure and fix

Before the fix, the first 327,680 complex samples of `stress_test.sigmf-data`
produced 481 OFDM decision symbols and 36 CSI/SNR tags, but **zero** `frame bytes`
or `encoding` tags and **zero** decoded packets. The kernel wrote zero to the
host's packet-start flag. After implementing the existing baseline flag contract,
the same build configuration produced 36 packet-start tags and **27 CRC-valid
packets**, byte-identical to the CPU LS receiver and the baseline NPU receiver.
All **23,088 symbol-decision bytes remained unchanged** by the fix.

## End-to-end results

All windows use the original 20 MHz `ci16_le` recordings read-only. Counts below
are MAC-decoder output PDUs, emitted only after FCS validation. "Identical" means
the same MAC bytes and duplicate packet counts, not merely equal packet totals.

| Recording/window (complex samples) | CPU LS | AI NPU | Packet bytes |
| --- | ---: | ---: | --- |
| Stress `[0, 327680)` | 27 | 27 | All identical |
| Stress `[0, 20004864)` (~1 second) | 5,166 | 5,166 | All identical |
| Room `[18001116414, 19001113854)` (~50 seconds), channel 10 | 17 | 17 | All identical |
| Bus `206` `[0, 400015360)` (~20 seconds) | 0 | 0 | Negative control, not decoding coverage |

The long stress window recovered encoding IDs 0, 4, 5, 6, and 7 (BPSK, 16-QAM,
and 64-QAM at their represented coding rates). The room window recovered BPSK
packets at 2457 MHz, testing a nonzero start offset and a different frequency RTP.
The initial bus window has no CPU CRC-valid output either; it must not be
reported as a successful packet-decoding test.

The short stress test also passed with **one host slot**: the same 27 packets
were recovered as with two slots. A relocated, bounded copy of the user's
`Experiments/quality_frames_rx/NPU/NPU.grc` was generated by `grcc` and executed
with the repaired production artifacts. Its Wireshark/radiotap PCAP contained
27 complete packets, with all MAC bytes identical to the CPU output. The user's
original GRC file and existing PCAPs were not modified.

The smaller **`MODEL=MLP_16`** was also built in a separate directory and tested
through the full eight-stage pipeline. It recovered the same **27** short-window
and **5,166** long-window stress packets, all byte-identical to the CPU reference.
The production build directory remains the default `MLP_16X16` configuration.
The updated ABI/alignment check compiled for both `aie2` and `aie2p`; all nine
existing host regression tests passed as well.
